## 0. 一句话结论

**完全不是大模型，也不联网。** 是一个本地跑的传统博弈 AI：

```
枚举所有合法出法  →  对每个出法模拟"出完之后我的手牌"  →  用估值函数打分  →  选分最低的
```

一次决策在 **2.1 ms** 左右（满手 27 张，困难档），这个数字本身就说明它不是在做搜索——
它只做了**一层的贪心**。

## 1. 决策流水线

```
decidePlay(game, player, difficulty)            ai.ts
  ├─ buildCtx()          收集上下文：难度参数、队友/对手剩牌、记牌表（如果该难度启用）
  ├─ game.target === null ?
  │    ├─ 是 → chooseLead()   首出：挑"出完之后手牌最好"的一手
  │    └─ 否 → chooseFollow() 跟牌：挑能压过目标的、代价最小的一手（也可以选择过牌）
  └─ 返回 { action, cards, reason }   ← reason 是中文，直接显示在界面上
```

`reason`（"出三带二（评估 -42）"、"代价过高，选择过牌"）不是给玩家看的装饰，
而是**调试接口**——出问题时能一眼看出 AI 当时在想什么。

## 2. 第一步：算出手里所有能出的牌

`enumeratePlays(hand, level, target, rules)`（`candidates.ts`）。

把手牌建成 `HandModel`：按点数分组 + 逢人配单独放 + 大小王单独放。
然后按牌型逐个生成：单张、对子、三同张、三带二、顺子、三连对、钢板、炸弹、同花顺、四大天王。

三个细节：

- **逢人配参与所有牌型**，不只补对子——它会去补顺子的缺口、凑三带二、补同花顺。
- **`target` 不为空时只留能压过的**（`beats`），所以 options 天然都是合法出法。
- **同一批牌只保留最强解释**：`红桃7 红桃8 红桃2 红桃10 红桃J` 既是顺子又是同花顺，
  按牌去重后只留同花顺，避免 AI 把同一批牌当成两个选项来比较。

## 3. 第二步：手牌估值

`evaluateHand(hand, level, rules)`（`handEval.ts`）——**这是整个 AI 的核心**。
它回答一个问题：**"这手牌还要几手才能出完？"**

### 3.1 两层：贪心 + 精确搜索

```
evaluateHand
  ├─ greedyDecompose()   贪心拆分：先拿炸弹、再拿钢板/连对/顺子、最后剩单张
  │                      给出一个稳定上界，也是 > 14 张时的快速估值
  └─ total ≤ 14 ? → solveExact()   带记忆化 + 节点预算的精确搜索，求真正的最小手数
```

`EXACT_LIMIT = 14`、`SEARCH_NODE_BUDGET = 20000`——超过预算就回退贪心上界。
这条预算很关键：**它保证 AI 永远不会卡住**，代价是超大牌型组合只得到近似值。

### 3.2 估值公式

```ts
score = hands * 100      // 还要几手（权重最大）
      + singles * 8      // 拆剩下的单张数量（负担）
      - control * 6      // 控制力：王、级牌、A、炸弹（能拿回出牌权的牌）
      - bombs * 12       // 炸弹数量
      - wilds * 4        // 手里还留着逢人配
```

**分越低手牌越好出。** AI 的整个决策就是"挑一个让这个分降得最多的出法"。

这里有个隐含的换算关系值得注意：**1 手 = 100 分**，而炸弹罚分是 140~200。
也就是说"为了少一手而烧一颗炸弹"在大多数情况下是**亏的**——这正是掼蛋的牌理。

## 4. 第三步：打分选最低

`chooseFollow` / `chooseLead` 里，每个候选出法的得分是：

```
score = 出完之后的手牌分 − 出之前的手牌分     ← 基础项：这一手让我变好了多少
      + spentValue(cards) * 2               ← 用掉的牌越大，越贵
      + 炸弹代价（见下）                      ← 只有炸弹才有
      + 位置项（队友/对手剩几张）              ← 局势判断
```

其中几个**最影响"像不像人"**的项：

| 项 | 含义 | 值（normal / hard） |
|---|---|---|
| `bombCost` | 炸弹代价，**随压制力单调递增** | 4张炸 140/200 → 5张炸 448/640 → 同花顺 602/860 → 6张炸以上封顶 |
| `followBonus` | 跟牌本身有成本（不该什么都跟） | 25 / 30 |
| `partnerPass` | 队友出的牌，通常让给他 | 200 / 260 |
| `threatBonus` | 对手快走完时，"拿回出牌权"的价值 | 0 / 210 |
| `oppLastCard` | 对手只剩 1 张——**所有难度都生效**的基础反应 | −120 |
| 队友赢牌不炸 | 想炸队友的牌要加 900 分（几乎不可能） | 固定 |

**炸弹阶梯**是最近才修对的：代价必须随压制力单调递增，AI 才会**先用够用的小炸**。
之前"只有炸弹能压"的场面会让同花顺免罚，结果 AI 拿着 4 张 K 炸不用、直接烧同花顺——
玩家一眼就看出来了。

### 4.1 还有几条写死的"常识"

- 能**一把出完** → 直接出（`afterHands === 0` 给 −1000000）
- **两手中能走完**且这手压不住 → 提前出（−100）
- 队友只剩 1 张且对手不危险 → **喂一张最小的单张**给队友
- 队友只剩 2 张 → 喂对子
- 对手只剩 1 张时 → 别送一张他能压过的单张

## 5. 记牌模块

`buildInfo(game, player)` 算出一张"外面还剩什么"的表：

```ts
rem[rank]        // 每个点数在别人手里还有几张 = 总数 − 已打出 − 我的手牌
unseenWilds      // 还没露面的逢人配数量
totalOutside     // 其他三家手牌总数
```

在这之上做了几层推断（只在 `useCounting` 的难度启用）：

- **`isTopNormal`**：我这手是不是当前最大？（单张/对子/三同张）
- **`bombPossibleOutside`**：外面还可能有炸弹吗？（4 张同点 / 双王 / 同花顺）
- **`bombBeatsExist`**：有没有**比我这颗更大**的炸弹还可能存在
- **`isUnbeatableWith`**：综合判断——这手是不是已经无人能压
- **同花顺的近似推断**：按花色统计"没见过"的牌，看哪个 5 张窗口的缺口数 ≤ 未见逢人配数

最后一条是**近似**（不是精确枚举），因为精确判断"别人有没有同花顺"需要知道他的手牌，
那是不可能的。这里用"缺口 ≤ 逢人配数"作为上界，偏保守。

## 6. 难度是怎么区分的

**不是靠搜索深度，而是靠一张参数表**（`paramsFor(difficulty)`）：

| 参数 | 简单 easy | 普通 normal | 困难 hard |
|---|---|---|---|
| `useCounting` 记牌 | ❌ 完全不记牌 | ✅ | ✅ |
| `useThreat` 威胁反应 | ❌ | ❌ | ✅ |
| `useBombs` 精确炸弹威胁 | ❌ | ❌ | ✅ |
| `bombPenalty` 炸弹代价基数 | 55 | 140 | 200 |
| `partnerPass` 让队友 | 120 | 200 | 260 |
| `threatBonus` 威胁时抢权价值 | 0 | 0 | 210 |
| `followBonus` 跟牌成本 | 0 | 25 | 30 |
| `randomize` 随机挑牌概率 | **0.45** | 0 | 0 |
| `randomPass` 随机过牌概率 | **0.25** | 0 | 0 |

所以三档的差别其实是三件事：

1. **简单档不作弊也不思考**：不记牌、不算炸弹威胁，而且 **45% 的概率从所有候选里随便挑一个**
   （不是挑最好的），还有 25% 概率直接过牌。所以它会放走能压的牌、会拆好牌。
2. **普通档会记牌，但只做"这手是不是当前最大"的判断**，不做炸弹威胁分析，也不为对手快走完而改变行为。
3. **困难档才会**：算"外面还有没有更大的炸弹"、在对手快走完时加权抢出牌权、更高的炸弹门槛。

**一个刻意的设计**：`oppLastCard`（对手只剩 1 张时 −120 分去拦截）**三档都生效**。
因为这是"基础 competence"——不这么做看起来像 bug，而不是像"弱"。

**难度设计的一个已知问题**：三档共用同一套评分公式，只改参数。所以"简单"不是"新手"，
而是"会打但经常故意打错"。真要做拟人化的新手，得改失误的类型（比如"会拆顺子"、
"会在该过牌时出大牌"），而不只是加随机。

## 7. 怎么证明它不弱

`src/test/aiBench.test.ts` 跑**自对弈基准**：

| 对局 | 结果 |
|---|---|
| hard vs easy | 36 : 0（100%） |
| normal vs easy | 36 : 0（100%） |
| hard vs normal | 约 50%（300 局实测 50.3%） |

外加一个性能断言：满手 27 张单次 `decidePlay` < 120 ms（实测 avg 2.1 ms）。

**必须知道这个基准的三个局限**，否则会误判：

1. **它只能测"相对强弱"，测不出"牌理"**。两个 AI 都犯同一个错时，胜率照样 50%——
   这正是"炸弹阶梯"那个 bug 能活下来的原因：它不影响总胜率方向，只是让 AI 打出不像人的牌。
2. **hard vs normal 本来就该接近 50%**。两档共用同一个估值器和走法生成器，
   差别只在炸弹精度和威胁反应，设计上就不是碾压关系。
3. **80 局样本的标准误约 ±5.6 个百分点**。所以看到 47% 或 53% 都不该当回事——
   这一点我们踩过：小样本得出"改动让它变差了"，扩大到 300 局后发现其实略好。

## 8. 为什么有时候不像高手

按影响从大到小，全部有代码依据：

### ① 只算一层，没有前瞻（最根本）

`chooseLead` / `chooseFollow` 只评估**出完这一手之后的静态手牌**。
它不知道"我先出这张，下一手就能接上"，也不知道"我忍一手，等对家先走完"。

人类会想 3~4 步，AI 只想 1 步。这解释了绝大多数"这手打得好奇怪"。

### ② 完全不用"过牌"这个信息

`buildInfo` 只统计**牌数**，不记录**谁在哪一轮跟不过什么**。

而在掼蛋里，"上家不要过顺子"是**极强**的信息——基本可以断定他没有顺子了，
接下来你出顺子就是安全的。人类玩家大量依赖这个，AI 完全没用。

### ③ 不推断对手手牌的形状

只有 `effCount`（某点数在别人手里最多几张）这种粗略上界。
不知道对手是"一手大牌等着控场"还是"一堆散牌在挣扎"，所以不会针对性地
"卡住他"或"放他走"。

### ④ 估值公式是全局面共用的固定权重

`hands*100 + singles*8 - control*6 - bombs*12 - wilds*4` 这一套对首出、跟牌、领先、落后
用的是同一套权重。但"控制力"在你领先时价值高、在你落后时价值低；
"单张负担"在剩 3 张时比在剩 20 张时要命得多。**现在这些都不区分。**

### ⑤ 没有终局求解

剩 5 张牌时人类算得清清楚楚（"他手上必是 X，我出 Y 他就完了"），
AI 还是跑同一套启发式。**终局恰恰是差距最明显的地方。**

### ⑥ 配合只有几条 if

- 队友剩 1 张 → 喂最小单张
- 队友剩 2 张 → 喂最小对子
- 别炸队友的牌

没有"谁主攻谁助攻"的判断，不会**主动给队友让路**（比如队友明显是主攻手时，自己该少抢风头），
也不会利用**接风**规则做战略布局。

### ⑦ 中段（normal / hard）完全确定性

`randomize = 0`，同一局面永远出同一手。玩久了玩家能摸清规律，
而且**同一个错误会每次重犯**——这比"随机犯错"更让人觉得笨。

### ⑧ 评价体系测不出这些

见第 7 节。**这是最需要先解决的**：没有能测"牌理"的手段，改进就只能靠感觉。

## 9. 改进方案

按"投入 / 收益 / 风险"分四档。**A、B、E 三档都不破坏"零依赖"约束。**

### A. 补常识与调参（1~2 天，立刻能感觉到）

| 编号 | 方案 | 说明 |
|---|---|---|
| **A1** | **权重自动调优** | 用现有 bench 当目标函数，对 `handEval` 的 5 个权重 + `ai.ts` 的若干罚分做**爬山 / 网格搜索**。纯机械，不需要人脑 |
| **A2** | 补几条牌理规则 | 例：剩"炸弹 + 单张"时先出单张；手里有明显主攻牌型时不要过早拆；对手只剩 2 张时优先出对子而非单张 |
| **A3** | 难度重设计 | 把"难度"从参数表改成 **搜索预算 + 故意失误率**：easy = 贪心 + 40% 随机；normal = 贪心 + 记牌；hard = 浅搜索；expert = 深搜索 + 终局求解。这样"简单"才像新手而不是像智障 |
| **A4** | 中段加少量随机 | 让 normal/hard 在"两个选项分差 < 阈值"时随机选，消除可被摸清的确定性 |

### B. 让它会"推理"（1~2 周，性价比最高）

| 编号 | 方案 | 说明 |
|---|---|---|
| **B1** | **过牌推断** ⭐ | 维护 `voidByType[player][type]`：某人跟不过某一牌型 → 大概率没有该牌型。**这是最便宜、最像人的一步**，而且改动只在 `ai.ts` 里加一个推断表 |
| **B2** | 手牌采样 | 从"未见过的牌 + 已知约束"里采样出对手的**具体手牌**（determinization）。是 C1 的前置 |
| **B3** | 估值加"被压概率" | 现在只能判"是不是当前最大"，可以补上"这手被压的概率有多大"（按未见牌数估算） |

### C. 让它会"算"（2~6 周，收益最大）

| 编号 | 方案 | 说明 |
|---|---|---|
| **C1** | **确定性蒙特卡洛（ISMCTS）** ⭐⭐ | 标准做法：① 采样 N 副符合观察的对手手牌 ② 每副里用现有贪心策略做 rollout ③ 选平均收益最高的动作。<br>**基础设施已经具备**：引擎有 `snapshot()/fromSnapshot()`，`aiStep` 就是现成的 rollout 策略。<br>代价：决策从 2 ms 涨到 50~200 ms（人感觉不出来），需要控制 N |
| **C2** | 终局精确求解 | 剩牌总数 ≤ K（比如 12 张）时改用完全信息搜索。终局是人类优势最大的区间 |
| **C3** | 时间预算制 | `paintingTimeMs(difficulty)`：给 AI 一个思考预算，在预算内尽量多跑 rollout。难度=预算，最自然 |

### D. 让它"学"（数周起，成本最高）

| 编号 | 方案 | 风险 |
|---|---|---|
| **D1** | 进化算法调权重 | CMA-ES / 遗传算法优化估值权重。**不需要神经网络，不破坏零依赖**，但收益上限低于 C1 |
| **D2** | 自我对弈强化学习 | 需要引入 ONNX / TF.js 运行时——**打破"单文件、零依赖"**，包体积会涨几十倍 |
| **D3** | 模仿人类牌谱 | 效果最好，但**没有数据**。如果你愿意录自己的对局，这条路的性价比会很高 |

### E. 评价体系（必须配套，否则改不动）

| 编号 | 方案 | 说明 |
|---|---|---|
| **E1** | **"牌理"测试集** ⭐⭐⭐ | 人工构造 50~100 个局面 + 高手应该怎么打，作为单元测试。**这是唯一能测出"像不像高手"的手段**，也是所有改进的前提 |
| **E2** | 保留自对弈 bench | 它测"没变弱"，和 E1 互补，两个都要 |
| **E3** | 决策耗时监控 | 现在有，扩展成"每个难度的预算上限" |

**E1 的具体做法**（建议先做这个）：从你实际玩到的"这手打得不对"的牌局出发，
把它固化成 `{局面, 期望出法, 理由}` 的用例。项目里已经有这个习惯——
比如 `aiBombLadder.test.ts` 里"手里同时有 4 张 K 炸和同花顺时，优先用 4 张 K 炸"
就是你报的一个 bug 变来的。

## 10. 推荐路径

如果目标是"**打起来像现实里的掼蛋高手**"，我会按这个顺序做：

```
第 1 步（1 天）  E1 牌理测试集 + A1 权重自动调参
                 ← 立刻能修掉一批"一眼就不对"的手
第 2 步（3 天）  B1 过牌推断 + A4 打破确定性
                 ← 最便宜的一次"像人"跃升：会利用对手的过牌信息
第 3 步（1 周）  C1 ISMCTS（先只给 hard 档）
                 ← 真正的质变；基础设施已具备，工作量主要在采样与预算控制
第 4 步           C2 终局求解 + C3 时间预算
                 ← 收尾：终局不再犯低级错
```

**每一档都要用 E1 + E2 两个尺子量**：E1 保证"更像人"，E2 保证"没变弱"。
只看 E2 会重蹈"炸弹阶梯"的覆辙——胜率没掉，但打出了不像人的牌。

**关于难度**：我建议改成四档并明确语义——

| 档位 | 实现 | 预期手感 |
|---|---|---|
| 新手 | 贪心 + 40% 随机 + 不记牌 | 会送牌、会拆好牌 |
| 普通 | 贪心 + 记牌 + 少量随机 | 中规中矩，偶尔失误 |
| 高手 | ISMCTS（小预算）+ 过牌推断 | 会卡人、会配合 |
| 宗师 | ISMCTS（大预算）+ 终局求解 | 终局不漏 |

## 附：一句话总结每一层

| 层 | 一句话 |
|---|---|
| `candidates.ts` | 把"我能出什么"穷举出来 |
| `handEval.ts` | 把"这手牌还要几手"算成一个数 |
| `ai.ts` | 把"每个出法让这个数变好多少"排个序，加上局势判断，选最好的 |
| `engine.ts` | 保证 AI 只能在合法的时候出合法的牌 |
| `autoplay.ts` | 把上面这些串成一局，供界面和基准测试共用 |

**没有神经网络，没有大模型，没有联网。** 全部是可以逐行读懂、逐项调参的传统博弈 AI。
