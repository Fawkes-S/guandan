# 江苏掼蛋 · 单机版 — 开发计划

> 目标：一款**离线可玩、规则严谨、AI 有脑子、画面好看**的单机掼蛋游戏。
> 单机 = 1 名真人 + 3 个 AI，无需联网、无后端。

---

## 一、视觉风格：推荐「水墨极简」（Ink Minimal）

你提到的两个方向其实可以合成一条主线，我推荐以**水墨极简**为主基调，理由与取舍如下：

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 纯水墨风 | 有辨识度、气质好、契合"掼蛋"的国风底色 | 满屏笔触会压低牌面可读性，27 张手牌叠在一起容易糊 | 作为**氛围层**使用 |
| 极简风 | 信息清晰、出牌决策快、性能好 | 容易做得像工具，缺乏记忆点 | 作为**信息层**使用 |
| **水墨极简（推荐）** | 宣纸底 + 极简牌面 + 墨色层次 + 朱砂点睛 | 需要克制，装饰元素要少而准 | ✅ 采用 |

**具体设计语言（Design Tokens）**

- 底色：宣纸米白 `#f4f1e8`，叠一层极淡的噪点/纤维纹理（CSS `radial-gradient` + `feTurbulence` 或纯 CSS 生成，不引入图片）。
- 墨色体系：焦墨 `#1c1c1e` / 重墨 `#2f2f33` / 淡墨 `#6b6b70` / 飞白 `#d8d4c8`。
- 点睛色：朱砂 `#b23a2f`（仅用于：级牌标记、逢人配标记、当前出牌方、报错提示）。
- 字体：标题用衬线（`"Songti SC", "STSong", "Noto Serif SC", serif`）；数字与牌点用等宽无衬线保证可读。
- 牌面：米白纸底 + 1px 墨线描边 + 圆角 8px + 极轻投影；花色用**墨色**符号，红桃/方块用朱砂。
- 动效：只用「淡入 + 轻微上浮 + 位移」，时长 180–260ms，`cubic-bezier(.2,.8,.2,1)`；炸弹用一次墨晕扩散。
- 布局：桌面对角座位（对家居中上方），底部为玩家手牌扇形/横排，右侧信息栏显示级牌、名次、出牌记录。

## 二、技术栈与工程形态

| 项 | 选择 | 理由 |
|---|---|---|
| 构建 | **Vite** | 秒级热更新，构建产物是纯静态文件，可直接双击 `dist/index.html` 离线玩 |
| 语言 | **TypeScript（strict）** | 规则引擎分支极多，类型是正确性的第一道防线 |
| UI | **原生 DOM + CSS**（不引入 React/Vue） | 牌桌需要精细的动画与层叠控制；零运行时依赖 = 启动快、无版本腐化 |
| 测试 | **Vitest** | 与 Vite 同源，规则引擎用单测钉死 |
| 依赖 | 仅 devDependencies，**运行时不依赖任何包** | 长期可维护、可离线 |

```
guandan/
├─ docs/            PLAN / RULES / PROGRESS / ARCHITECTURE
├─ index.html
├─ src/
│  ├─ core/         纯逻辑，零 DOM，可单测
│  │  ├─ types.ts       牌、花色、牌型枚举
│  │  ├─ cards.ts       牌堆、排序、比点、随机数（可复现）
│  │  ├─ combos.ts      牌型识别（含逢人配枚举）
│  │  ├─ compare.ts     大小比较、压制判定
│  │  ├─ candidates.ts  合法出牌枚举（AI 与"提示"共用）
│  │  ├─ handEval.ts    手牌估值（最少手数 / 控制力）
│  │  ├─ rules.ts       规则配置（可切换的地方规则）
│  │  ├─ tribute.ts     进贡 / 还贡 / 抗贡
│  │  ├─ engine.ts      对局状态机（发牌→进贡→出牌→名次→升级→过A）
│  │  └─ ai/            AI 决策（三档难度）
│  ├─ ui/           渲染与交互
│  └─ test/         单元测试
└─ dist/            构建产物（离线可玩）
```

**核心设计原则**：`core` 是纯函数式的确定性状态机（注入种子随机数），`ui` 只做「渲染 state」+「派发 action」。这样 AI 自动对局、复盘、单元测试、录像回放全部免费获得。

## 三、规则基线（江苏 / 淮安主流规则）

完整版见 `docs/RULES.md`，摘要：

- 2 副牌 108 张，4 人，**对家为队友**，逆时针出牌。
- **级牌**大于 A、小于小王；**红桃级牌 = 逢人配**，可替代除大小王外任意牌。
- 牌型：单张、对子、三同张、三带二、顺子（仅 5 张）、三连对（木板）、三连同张（钢板）、炸弹（4–10 张）、同花顺、四大天王。
- 压制序：四大天王 > 六张及以上炸弹 > 同花顺 > 五张及以下炸弹 > 普通牌型。
- 升级：头游+二游升 3 级；头游+三游升 2 级；头游+末游升 1 级。
- 进贡/还贡/抗贡、接风（对门借风）完整实现。
- 过 A：需「一人上游、另一人非末游」才算取胜；三次不过 A 按配置降回 2 重打。

## 四、里程碑与验收标准

| # | 里程碑 | 交付物 | 验收标准 |
|---|---|---|---|
| M0 | 脚手架 | Vite+TS+Vitest 工程 | `npm run dev/build/test` 三条命令均通过 |
| M1 | 牌型引擎 | `cards/combos/wildcard` | 全牌型识别单测通过，含逢人配替代与非法牌型拒绝 |
| M2 | 比较与枚举 | `compare/candidates` | 压制序、同型比点、炸弹序、A 低顺子全部有测试 |
| M3 | 对局状态机 | `engine/tribute` | 能跑完一整局：发牌→进贡→出牌→接风→名次→升级；含过 A 终局 |
| M4 | AI | `ai/` | 三档难度可调；AI vs AI 自动跑 100 局无非法动作、无死锁 |
| M5 | 水墨 UI | `ui/` | 可完整手动打完一局，动画流畅、牌面清晰 |
| M6 | 体验完善 | 提示/理牌/歧义选择/设置/存档 | 逢人配歧义可选择；刷新可续局；提示永不给出非法牌 |
| M7 | 收尾 | 测试+构建+文档 | 测试全绿、`dist` 离线可玩、PROGRESS 更新完毕 |

## 五、风险与对策

| 风险 | 对策 |
|---|---|
| 逢人配导致牌型歧义爆炸 | 先按"自然解释"识别，再对 ≤2 张逢人配做有界枚举（52² 上界），结果去重并按压制力排序；UI 提供歧义选择器 |
| AI 出牌合法但不合理 | 用「最小手数」估值函数给候选打分；建立 AI vs AI 自动对局回归（跑 100 局验证无非法/无死锁） |
| 规则地区差异 | 所有分歧点集中在 `rules.ts` 配置项（A 在连对/钢板中是否作 1、还贡上限、过 A 条件、三次不过 A 处理） |
| 27 张手牌在移动端显示不下 | 手牌两行自动换行 + 自适应缩放；首选桌面端体验 |
| 大模型改动破坏核心逻辑 | 核心逻辑全部有单测钉死；每次改动必须 `npm test` 全绿 |
